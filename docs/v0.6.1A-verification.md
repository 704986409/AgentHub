# V0.6.1A — Static Route Identity / Dynamic Agent Status Projection Closure

Baseline: `a7e2a2e3c83e5848f2ee8e6d72e355f8b8eed6f4` (`0.6.1`). V0.5 remains sealed and V0.6.2 has not begun.

## Result

- `routePlanSha256` now hashes explicit task, agent, provider, and requirement identity projections instead of internal routing snapshots.
- Agent identity represents only the derived static enablement semantic. Raw `AgentStatus` and raw `enabled` are excluded from the digest.
- IDLE, BUSY, and OFFLINE remain eligible and now produce the same plan digest when every static routing input is equal.
- Equivalent disabled representations canonicalize to one static identity while an enabled-to-disabled transition changes both eligibility and digest.
- Candidate ordering, rejection vocabulary, public route schema, and all V0.6.1 eligibility behavior remain unchanged.
- No AgentPool, runtime availability, assignment, reservation, task mutation, retry, scheduler, or provider-session behavior was added.
