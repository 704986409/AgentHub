# V0.7 Pre-commit Failure Matrix

The transport is observational and never mutates authoritative state directly. The table records the fail-closed boundary used by the local API.

| Failure | Transport result | Core state | Retry safety | Side effects |
|---|---|---|---|---|
| listen failure / port in use | start rejects | unchanged | new server/port may retry | none |
| invalid host | 400 before listen | unchanged | safe | none |
| malformed / oversized JSON or disconnect | 400 / 413 | unchanged | safe with a complete request | none |
| idempotent duplicate | cached/joined response | first result | same operation is not rerun | first request only |
| idempotency mismatch | 409 | unchanged by conflicting request | new key required | none from conflicting request |
| scheduler no candidate | 409 | scheduler authoritative result | fresh retry allowed | no provider turn |
| dispatch failure | mapped safe 4xx/5xx | dispatcher reconciliation rules apply | same key retries only after failed entry is removed | dispatcher-defined |
| runtime reconciliation required | 503 | core remains authoritative | operator reconciliation required | may have occurred |
| evidence blocked / revision failure | 422 | lifecycle authoritative state | failed idempotency entry removed | lifecycle-defined |
| review handle expired / stale | 410 / 409 | unchanged | new review handle required | none |
| merge denied | 200 outcome | review remains available | cached for same key | no merge |
| merge completed | 200 outcome | completed | same key returns cached result | one merge |
| post-merge reconciliation required | 503 | core records reconciliation need | no blind retry with changed request | merge may have occurred |
| invalid WebSocket upgrade | connection rejected | unchanged | reconnect correct route | none |
| WS serialization/send failure | client isolated | unchanged | reconnect + state query | none |
| slow WS client | client closed with 1013 | unchanged | reconnect + state query | none |
| server stop with clients | clients terminated, listener closed | application graph remains owned by caller | create a new server instance | no core mutation |

Review handles are process-local, immutable, claimed during decisions, and expired after completion or revision. HTTP bodies cannot supply reservations, dispatch results, review evidence, merge decisions, task review bundles, paths, commands, environment, or provider executables.
