## AgentHub result

The mandatory integration test passed in 748 ms. Its trace verified this exact
order:

1. Process spawned and remained live (PID recorded).
2. AgentHub sent the minimal `initialize` request with ID `1` and a trailing
   newline.
3. The corresponding response arrived on stdout.
4. AgentHub sent `initialized`, also newline-terminated.
5. Provider became `READY`, then shut down gracefully to `STOPPED`.

The test also verifies that `initialized` cannot be sent before the initialize
response and that inbound messages are classified by message shape rather than
requiring `jsonrpc: "2.0"`.

## Official baseline

Command run in the same environment:

```text
codex debug app-server send-message-v2 "Reply with exactly OK."
```

The official client successfully completed its own `initialize` handshake,
sent `initialized`, received `thread/start`, and received `turn/start`.
This proves that the original initialize timeout was an AgentHub client
implementation issue, not a Windows/Codex App Server handshake limitation.

The command exited with code `0`, but the requested answer was not produced:
the selected model reported `serverOverloaded` ("Selected model is at capacity")
after transport retries. That is an upstream model-capacity event after the
handshake and task dispatch, not a protocol-handshake failure.

`CODEX_HOME` was unset in the shell; the App Server reported its effective home
as `C:\Users\70498\.codex`. No authentication values were logged.
