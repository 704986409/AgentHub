# V0.6.1 — Deterministic TaskRouter / Static Eligibility + Ranking Plan

Baseline: `d0b63026dfb72a4c92d4b130c7c1343358da00bd` (`0.5.5A`). V0.5 remains sealed.

## Result

- Added a pure, provider-neutral `TaskRouter` that consumes only task routing fields, agent routing fields, provider capability snapshots, and explicit routing requirements.
- Eligibility covers enabled state, project scope, complexity, risk, exact capability/specialty sets, authority, provider presence, and required output protocols while keeping BUSY and OFFLINE agents statically suitable.
- Eligible agents are ordered by routing priority descending, project scope before global scope on equal priority, then lexical agent ID. Provider, model, position, name, input order, and unrelated extra skills never affect rank.
- Every rejected agent receives all applicable reasons in one fixed order. Rejections are sorted by agent ID.
- Duplicate agent and provider identities, malformed values, hostile getter failures, and bounded-input violations fail with stable TaskRouter errors.
- All nested inputs are detached and canonical set fields are deduplicated and ordinally sorted. Caller mutation cannot change an existing plan.
- `routePlanSha256` binds the versioned normalized routing snapshot, provider descriptors, requirements, final candidates, and rejection diagnostics while excluding descriptive fields and timestamps.
- The route plan and all nested result collections and entries are deeply frozen.
- The router has no database, service, EventBus, AgentPool, runtime, provider-session, filesystem, Git, model, or free-text profile dependency. It creates no assignments and mutates no Task or Agent.
