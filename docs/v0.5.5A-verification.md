# V0.5.5A — Merge Semantic Determinism / Branch MergeOptions Closure

Baseline: `bd7bd10754a727c691883b4ca6f92e18739bca3a` (`0.5.5`).

## Result

- Any effective `branch.<target>.mergeOptions` value is rejected before task/gate work, again before conflict preflight, and again immediately before mutation.
- Named `merge=<driver>` attribute selections are rejected for every affected path in the live primary view, target tree, and task tree, even when no matching driver is configured.
- Built-in `merge` set, unset, and unspecified states remain allowed. Existing filter selection restrictions remain unchanged.
- Trusted `git merge-tree --write-tree` preflight now returns a validated immutable expected tree OID bound to the captured target and task commit OIDs.
- A normal merge returns `merged` only when `HEAD^{tree}` exactly matches the expected preflight tree, in addition to all existing parent, cleanliness, task branch, task worktree, and base-marker postconditions.
- A post-mutation tree mismatch returns `GIT_MERGE_CLEANUP_FAILED` and permanently quarantines repository merge authority.
- No runtime/provider, database, migration, remote Git, evidence, review, gate, worktree lifecycle, or coordination behavior changed. Real model calls: 0.
